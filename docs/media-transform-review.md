# v18 검수 기록

## 구현 범위

- 기존 cue(시간 구간), 또는 cue가 없는 원본 scene에 `transform: {scale, x, y}`를 저장합니다. scale은 배율, x/y는 영상 영역 대비 비율입니다. 값이 없는 기존 장면은 1/0/0으로 렌더링됩니다.
- 변환을 수정할 때 객체를 교체하여 나누기로 이어받은 두 장면도 이후 독립적으로 편집됩니다. cue 편집은 기존 되돌리기에 포함됩니다.
- `timelineScenes()`에서 변환을 전달하고 `CutRenderer.mediaGeometry()`에서 fit → 기본 배율 × 카메라 배율 및 위치를 계산합니다. 기존 draw 경로와 전환 클리핑을 그대로 사용합니다.
- 미리보기와 WebCodecs/FFmpeg 출력 경로는 모두 기존 `CutRenderer.draw()`를 호출합니다. 인코더 코드는 변경하지 않았습니다.
- 새 JS/CSS는 기존 PC/모바일이 이동해서 쓰는 편집 영역에 컨트롤 한 세트만 추가합니다. 제스처는 조절 모드를 켰을 때만 활성화하며, 이때에만 기존 스와이프 처리를 차단합니다.

## 통과한 자동 검증

`npm test` / `npm run build`

- 기존 타임코드, 구간 나누기/합치기/되돌리기, 자막 스타일, 글자 색상, 제목·채널명, 장면 선택 회귀 테스트.
- 장면별 독립 값, 같은 원본을 참조하는 구간 분리, 이동 후 유지, 초기화와 되돌리기.
- 이미지/영상에 동일한 변환 좌표 적용. 기본값의 기존 구도 유지.
- 360/720/1080 너비, 세 가지 레이아웃, cover/contain에서 정규화된 출력 좌표 일치.
- 실사용 제스처 이벤트 핸들러를 모의 DOM에서 호출: 한 포인터 드래그, 두 포인터 핀치, 핀치 후 한 손가락 이동, 숫자 Scale 변경, 리셋.
- 카메라 팬+줌 중 핀치 중심 고정 및 사용자 배율 결합.

## 확인하지 못한 사항

이 환경에 브라우저 실행 파일이 없고 설치 다운로드도 실패하여 실제 브라우저 화면 및 실제 휴대폰 테스트는 수행하지 못했습니다. MP4 인코딩 결과 파일의 육안 비교도 수행하지 못했습니다. 위 좌표 일치 검증은 공유 렌더러의 계산 결과 검증이며 최종 인코딩 테스트를 의미하지 않습니다.

실제 기기 확인 순서: 이미지·영상 메뉴 → 미리보기에서 조절 → 드래그/핀치 → 다음/이전 장면 → 값 유지 확인 → 초기화 → 카메라 무빙 설정 → 전체 화면 확인 → MP4 저장 후 구도 비교. 모바일에서 조절 모드를 껐을 때 세로 스크롤 및 장면 스와이프도 확인하세요.
