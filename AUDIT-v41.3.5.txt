Cutflow v41.3.5 UI mode audit

Confirmed deployment facts
- GitHub Pages workflow builds root files into dist and deploys dist.
- Latest Pages workflow completed successfully.
- Deployed artifact contains all 35 assets referenced by index.html.
- All deployed JavaScript files pass node --check.
- Initial HTML contains no duplicate IDs.

Root causes found
1) mobile-ui.js and desktop-ui.js decide mode independently.
   mobile-ui.js can activate a mobile device even when its layout viewport is desktop-sized.
   desktop-ui.js then loads afterwards and only checks matchMedia('(min-width:761px)'), so it can activate desktop UI on the same phone.

2) The cutflow-mobile-activate event is not sufficient at initial load.
   mobile-ui.js is loaded before desktop-ui.js, so the event can fire before desktop-ui.js registers its listener.
   desktop-ui.js then calls activate() unconditionally at the end of its own initialization.

3) desktop-ui.js used MediaQueryList.addEventListener without the older addListener fallback.
   In Safari/WKWebView environments lacking that method, desktop-ui.js can stop before its final mode setup.

4) mobile-ui.css still contained viewport-authoritative hiding.
   A desktop-sized mobile viewport could hide .mobile-only even when JS had already selected mobile mode.

5) Existing mobile regression tests did not test mobile/desktop mutual exclusion.
   Previous patches could pass tests while desktop-ui still reclaimed the DOM afterwards.

v41.3.5 changes
- Shared window.CutflowUI mobile mode registry.
- Broader desktop-site touch-device fallback.
- mobile activation explicitly removes desktop-editor.
- desktop activation refuses to run while mobile mode is active.
- desktop initial boot now calls syncDesktopMode(), not activate().
- mobile activate/deactivate events synchronize desktop mode.
- MediaQueryList addEventListener/addListener compatibility in desktop-ui and mobile-fullscreen.
- CSS mode class is authoritative; body.mobile-editor hides all desktop-only UI.
- Mobile layout media range broadened so iPhone desktop-site viewports still receive the intended layout.
- Cache keys bumped for every changed runtime file.
